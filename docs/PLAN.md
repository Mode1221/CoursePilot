# 프로젝트 기획안: 코파일럿 기반 자율 검증형 모임 동선 플래너 (CoursePilot)

## 1. 프로젝트 개요
- **프로젝트명**: CoursePilot (코스파일럿)
- **핵심 목적**: 사용자의 모임/데이트 조건(시간, 취향, 동선)을 자연어로 입력받아, 장소 API와 지도 데이터를 기반으로 물리적 제약(영업시간, 이동 거리)이 검증된 최적의 타임라인을 자동 생성 및 시각화하는 웹앱.
- **핵심 가치**
  - 사용자 측면: 앱 설치 마찰 없이 링크 클릭만으로 즉시 실행되는 'Zero-Friction' 경험. 어떤 채널로 공유되든 동일하게 동작.
  - 기술적 측면: AI 할루시네이션을 외부 지도/장소 API 검증 파이프라인으로 원천 차단하는 에이전틱(Agentic) 구조.

## 2. 기획 배경 및 문제 정의
- 일반 LLM: 폐업/브레이크타임/불가능한 이동거리 등 물리적 제약 무시한 할루시네이션.
- 기존 큐레이션 앱: 고정 프리셋만 제공, 유동 조건 미반영.
- 접근성: 단발성 약속에 네이티브 앱 설치·가입은 심각한 이탈 유발.

## 3. 유저 저니 맵 — '메신저 비종속 링크 루프'
1. **진입**: 공유 링크(`domain.com/plan/xxx`)를 어떤 메신저에서든 클릭.
2. **구동**: 표준 웹뷰에서 '지도 + 챗봇' 분할 화면(Split-Pane) 즉시 렌더링.
3. **조작**: AI와 대화로 코스 생성, UI로 상세 확인·직접 수정.
4. **공유**: Web Share API 공유, 카카오 환경은 카카오 SDK 폴백.
- 여러 명이 동시에 같은 링크로 접속해 편집 가능(5장 참고).

## 4. 핵심 기능 요구사항
하이브리드 UI: [시각화 패널(지도)] + [챗봇 패널].
- **4-1 자연어 조건부 코스 생성**: 자연어 입력 → AI 분석 → 지도 마커·리스트 렌더링.
- **4-2 장소 상세 정보 모달**: 장소 카드 클릭 → 영업시간·별점·리뷰 요약 확인.
- **4-3 AI & 수동 하이브리드 동기화 제어**
  - AI 제어: 챗봇 명령으로 특정 카드 교체 후 전체 동선 재계산.
  - 수동 제어: 드래그앤드롭 순서 변경/삭제.
  - 수동 조작 시 프론트가 즉시 길찾기 API 호출해 리렌더링, AI 상태와 동기화.
- **4-4 한눈에 보기**: 핀을 선분으로 연결해 동선 시각화.
- **4-5 상태 저장 및 공유 루프**: 완성 코스를 JSON 상태로 DB 저장, 고유 URL 발급. 공유 대상은 픽스된 최종 타임라인만 열람.

## 5. 동시 편집(실시간 동기화) 정책
- **5-1 기본 원칙**: 단일 상태(Single Source of Truth) + 액션 큐 직렬화. "서버 도착 순서" 기준 순차 처리 → CRDT 없이 N명 확장.
- **5-2 채팅 vs UI 상태 구분**: 채팅 로그는 append-only. 타임라인/지도 상태가 실제 충돌 지점.
- **5-3 AI 처리 중 UI 편집 잠금(Lock)**: 처리 중 `locked` broadcast → 프론트 편집 즉시 차단(토스트). 완료 시 `unlocked`. 액션 큐로 한 번에 하나의 AI 요청만 lock 보유.
- **5-4 인프라**: Socket.IO 세션별 room broadcast. 캐시 유실 시 서버 refetch + 자동 재연결. (선택) "누가 편집 중" 표시.

## 6. 기술 스택
### Frontend
- Next.js(React) + TypeScript. 표준 반응형, 웹뷰 제약만 고려.
- Zustand: 수동 조작과 AI 응답(JSON)을 하나의 상태로 관리.
- 지도/장소 API 어댑터 레이어: `mapService.searchPlaces()`, `mapService.getRoute()` 등 추상화. 초기 구현체 Naver Map 기준.
- 공유 어댑터 레이어: `shareService.share(url)`. 기본 Web Share API, 카카오 감지 시 카카오 SDK 폴백.

### Backend
- Python + FastAPI: AI 추론 파이프라인 및 비동기 처리.
- PostgreSQL + pgvector: 코스 JSON, URL Hash 매핑, 리뷰 임베딩 통합 관리.
- Socket.IO(python-socketio): AI 응답 스트리밍 및 동시 편집 broadcast.

### AI & Data Pipeline
- GPT-4o(-mini) 또는 Claude API: 자연어 분석 + Function Calling.
- 장소 검색/길찾기 API(어댑터 경유, 초기 Naver): 실제 영업 확인 및 이동 거리/시간 계산.
- 파인튜닝 불필요. 모델 역할은 "파싱 + API 호출"로 한정, 사실은 API가 제공.

## 7. 에이전틱 검증 파이프라인
1. **Decomposition**: 문장을 [지역][조건][시간] JSON으로 파싱.
2. **Tool-Use**: 장소 API 어댑터로 반경 내 후보 10개 수집.
3. **Validation**: 브레이크타임·영업여부 대조, 길찾기로 이동시간 조건 초과 여부 계산, 위반 장소 폐기.
4. **조건 완화 재시도(Fallback)**: 유효 후보 부족(0~2개) 시 소프트 제약부터 단계적 완화. 하드 제약(예산 상한)은 유지. 1차 완화로도 부족하면 사용자에게 확인.
5. **Final Response**: 모든 제약 통과한 장소·타임라인만 전달.

## 8. 리뷰 데이터 수집 및 신뢰도 필터링
- **방식**: 파인튜닝이 아닌 RAG. 리뷰를 pgvector 임베딩으로 저장, 생성 시 검색 참조.
- **출처 주의**: 네이버 지도 리뷰 API 미제공, 크롤링 지양. 대안으로 네이버 블로그/카페 검색 API로 텍스트 수집·요약.
- **협찬/체험단 필터링**
  1. 1차 키워드/패턴 필터링("협찬","체험단","제공받아" 등 + 계정 패턴).
  2. 2차 LLM 판단(프롬프트로 협찬 여부 제외 지시).
- **한계**: 은닉 협찬 탐지 불가. "명백한 협찬글 제외 + 나머지 참고용" 현실적 목표.

## 9. 비즈니스 모델 및 사용자 정책
- **9-1 과금 단위**: 세션(코스) 크레딧. 생성자가 소비, 편집자는 같은 풀에서 차감. 수동 편집은 항상 무료, AI 명령만 차감.
- **9-2 무료 정책**: 전화번호 인증 회원에게 월 N회 무료 크레딧, 이월 불가. 소진 시 포인트 구매 유도(강제 X, 수동 편집 계속 무료).
- **9-3 참여자 권한**: 로그인 없이 링크 접속만으로 참여. 수동 편집만 가능, AI 질의 불가(크레딧 책임을 생성자로 한정).
- **9-4 리텐션**: 마이페이지 히스토리, 북마크(타인 코스 포함), 레퍼럴 크레딧.
- **9-5 사용량 표기**: 내부는 토큰·비용 정확 트래킹, 사용자에겐 "질문 N회 남음"으로 환산 노출. 완화 재시도도 "질문 1회"로 통일.
- **9-6 온보딩 선호도 사전조사**: 가입 시 3~5문항(분위기/예산/지역/음식제약/이동수단), 모두 건너뛰기 가능. 프로필은 매 AI 요청 컨텍스트에 자동 포함.
