# AI 코스 품질 향상 방법 탐색

"물리적으로 가능한 코스"에서 "**사용자에게 최고인 코스**"로 끌어올리기 위한 방법 정리.

## 현재 파이프라인의 한계 (코드 기준)
`agent._attempt` → `search_places(limit=10)` → `build_timeline(후보 순서 그대로)`.

1. **탐욕적 순서 배치**: 검색이 준 순서대로 넣고 영업/이동/예산만 검증. 동선(이동 최소화)이 핵심 가치인데 **최적화하지 않음**.
2. **후보 선택이 무평가**: 통과하는 앞 N개를 그대로 사용. 평점·키워드 적합·리뷰·다양성으로 **랭킹하지 않음**.
3. **코스 구조 부재**: 좋은 코스는 보통 식사→카페→활동 흐름인데 **카테고리 시퀀스 개념이 없음**.
4. **키워드가 검색어로만 쓰임**: "조용한/비건" 등이 선택 점수에 반영되지 않음.
5. **리뷰(RAG) 미활용**: 상세 모달에서만 쓰고 장소 선택엔 안 씀.
6. **완화가 단조**: max_travel_min 1회 *1.5. 제약 우선순위·대화형 재질문 없음.
7. **선호가 가중치가 아님**: 온보딩 프로필이 빈 필드만 채우고 랭킹엔 무영향.
8. **목적함수 부재**: 생성된 코스의 "좋음"을 수치화하지 않아 **대안 비교/‘최고’ 선택 불가**.

## 제안 방법 (효과·구현비용 순)

### A. 후보 스코어링 + 랭킹 (효과 높음 / 비용 낮음) ⭐
장소별 적합도 점수:
```
score = w_rating·norm(rating)
      + w_kw·(카테고리·이름이 키워드/무드와 매칭되는 정도)
      + w_budget·(예산 대비 가격 여유)
      + w_pref·(온보딩 선호 일치)
```
통과 후보를 점수 내림차순으로 정렬 후 배치 → 같은 제약이라도 "더 좋은" 장소 우선.

### B. 카테고리 시퀀스 템플릿 (효과 높음 / 비용 중간) ⭐
소요시간·시간대로 코스 골격 결정 후 슬롯별 최고 점수 후보 배치:
- 3시간 점심대 → [식당, 카페] / 5시간 → [식당, 카페, 활동] / 저녁대 → [식당, 바]
- 슬롯당 카테고리를 강제해 "카페만 3개" 같은 단조 코스 방지(다양성).

### C. 동선 최적화 (효과 높음 / 비용 중간) ⭐
후보를 nearest-neighbor로 정렬해 총 이동거리 최소화(간단 TSP 근사). 시작점은
지역 중심 또는 첫 슬롯 최고 후보 고정.

### D. 코스 목적함수 + Best-of-N (효과 높음 / 비용 중간) ⭐
여러 시드(정렬/시작점)로 후보 코스 K개 생성 → 코스 점수로 최고 선택:
```
course_score = -α·총이동분 + β·평균평점 + γ·카테고리 다양성
             + δ·키워드/선호 충족 - (제약 위반 페널티)
```
"물리적으로 가능"을 넘어 "**정량적으로 최고**"를 고를 수 있게 됨.

### E. 리뷰 근거 선택 (효과 중간 / 비용 중간)
RAG로 후보의 비협찬 리뷰 감성/키워드를 뽑아 스코어에 반영("조용한"이 리뷰에 실제
등장하는가). 할루시네이션 없이 실제 후기 기반 선택.

### F. 자기 비평·반복 (효과 중간 / 비용 높음)
생성 코스를 LLM이 평가 → 약한 슬롯만 교체 후 재검증(generate→critique→refine 루프).
비용(크레딧)과 지연 증가 → 옵션/프리미엄으로.

### G. 대화형 조건 완화 (효과 중간 / 비용 낮음)
현재 needs_confirmation을 넘어, 어떤 제약을 얼마나 완화할지 사용자에게 선택지 제시
("도보 10→15분" vs "지역 확장"). 완화 우선순위: 소프트(이동 여유)→암묵→하드(예산)는 마지막.

## 이번 구현 범위
A+B+C+D를 `pipeline/planner.py`로 구현하고 `_attempt`를 교체한다. 외부 키 불필요,
결정론적이라 테스트 가능. E/F/G는 후속(키·비용·UX 필요).
